# 03. 지역/품목 코드 매핑 분석

## 3.1 지역 코드 — 소스마다 다름 (최대 난점)
| 소스 | 지역 표현 | 예시 | 표준화 |
|------|----------|------|--------|
| KAMIS | 시장명/지역명 | "서울가락", "부산엄궁", "수원" | 시장→시도 매핑 |
| MAFRA 경락(654) | whsl_mrkt_cd(6자리) + plor_nm(산지 풀네임) | "110001", "강원특별자치도 평창군" | 파싱 필요 |
| MAFRA 저수율(669) | AREA_SPR_CD(저수지코드) | "489","143" | **시군구 매핑 불가** |
| MAFRA 특보(671) | BJDNGCD(법정동코드) | "1100000000","4111000000" | 표준(앞2=시도, 앞5=시군구) |
| KOSIS | 행정구역코드 | 시도/시군구 | 표준 근접 |
| 우리 시스템 | KR-XX(시도) + 시군구명 | "KR-42", "평창군" | 내부 |

### 문제
- "수원 / 수원시 / 경기 수원 / 수원시 권선구"처럼 **같은 지역이 다르게 표현**.
- 저수율은 저수지코드라 행정구역과 직접 매핑 불가(별도 코드표 필요).

### 해결 (권장)
1. **표준 = 법정동코드(BJDNGCD)** 채택. 시도(2)·시군구(5)·읍면동(10) 계층.
2. `region_map` 마스터 테이블: {source, source_code/name} → {bjd_cd, sido, sigungu}.
3. plor_nm(산지 풀네임) → 정규식 파싱(시도 첫토큰) 후 시군구 매칭. (현재 _origin_sido 시도까지 구현)
4. 저수율 AREA_SPR_CD → 농어촌공사 저수지-시군 매핑표 확보 전까지 **전국 지표로만** 사용.

## 3.2 품목 코드 — 소스마다 다름
| 소스 | 품목 표현 | 예시 |
|------|----------|------|
| KAMIS | productno | 28=배추, 64=무, 117=양파, 1003=마늘 |
| MAFRA 경락 | gds_lclsf/mclsf/sclsf_cd(대/중/소분류) + 품종명 | 배추>얼갈이배추/봄배추/고랭지배추 |
| 우리 시스템 | item_code | cabbage/radish/onion/garlic/green_onion |

### 문제 (정확도 핵심)
- "토마토 / 방울토마토 / 대추방울 / 토마토(일반) / 토마토(시설)"처럼 **품종이 세분**되고 가격이 전혀 다름.
- 배추: 고랭지배추(여름 프리미엄) vs 봄/월동배추 vs 얼갈이배추 — **하나로 묶으면 평균 왜곡**(이미 확인됨).

### 해결 (권장)
1. `item_map` 마스터: {source, source_code} → {item_code, variety_code}.
2. **2단 구조**: 대표품목(배추) + 품종축(고랭지/봄/월동). 예측·수집을 품종별로 분리.
3. 표준품종 필터(_is_std_variety)로 혼입 방지(구현됨), 향후 품종별 개별 모델.

## 3.3 매핑 필요성 결론
- 지역·품목 **매핑 마스터 2종 필수**. 이것이 Feature Store 조인의 전제.
- 미구축 시: 소스 간 조인 불가 → 통합 학습 불가.
