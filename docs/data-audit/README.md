## 최종 질문 답변 (요약)

**Q1. 어떤 데이터를 사용할 것인가?**
핵심(A급): KAMIS 가격(2013+), MAFRA 실시간경락(654), KMA 기상, MAFRA 저수율(669)·물량(658).
보강(B급): KOSIS 생산/재배면적, MAFRA 도매(217)/소매(163)/친환경(160)·특보보험(671).
연구(C급): FarmMap 병해충·토양, 관세청 수입, 환율, 통계청 소비.

**Q2. 데이터 양은 충분한가?**
가격은 **10년+ 일별**로 충분. 기상은 예보만 실시간, **과거 관측(ASOS/AWS)은 별도 백필 필요**.
생산·재배는 **연별**이라 시즌 피처로만. 저수율/특보는 **월별 7년+**.

**Q3. 품질은 학습에 적합한가?**
가격은 이상치·품종혼입·단위 이슈가 있으나 이미 가드 구축(품종필터·이상치제거·단위정규화).
지역/품목 **코드 불일치**가 최대 난점 → 표준 매핑 필요.

**Q4. 하나의 Feature Store로 통합 가능한가?**
가능. 조인키 = **품목(item_code) × 지역(표준 법정동/시도) × 날짜**.
시간축이 다른 데이터(월/연)는 forward-fill·시즌화로 일별에 정렬.

**Q5. 치명적 제약은?**
① 지역코드 이질성(저수율=저수지코드, 특보=법정동, KAMIS=시장명) — 매핑 테이블 필수
② 품종 세분(고랭지/봄/월동 배추가 별개 가격) — 품종축 필요
③ **KOSIS 제공키 무효**, **FarmMap 키 401** — 재발급/검증 필요
④ 과거 기상 관측 백필 부재

**Q6. 부족한 데이터와 보완책은?**
- 과거 기상 관측 → KMA ASOS/AWS 별도 수집(백필)
- 병해충·토양 → FarmMap 키 정상화 or 농진청 API
- 수입/환율/소비 → 관세청·한국은행·통계청 추가 연동
- 지역 매핑 → 법정동코드(BJDNGCD) 표준 채택
